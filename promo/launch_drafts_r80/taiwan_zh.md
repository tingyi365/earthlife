**內文：**

各位鬼島同業午安，

先講結論：我寫了一個文字人生模擬器《地球 Online》，然後就不寫了——把整個 repo 丟給一個 AI agent，讓它每輪自己選題、自己改 code、自己跑測試、自己部署。到現在 79 輪，它比當初的我還守規矩。

線上即玩（純中文）：https://earthlife.pages.dev
開源（MIT）：https://github.com/tingyi365/earthlife

**那個迴圈長這樣：**
1. agent 讀現在的程式碼 + 前幾輪自己留在原始碼裡的設計註解（那個檔案就是它的長期記憶）
2. 挑這輪要做什麼：新機制 / 數值平衡 / 打磨 / 彩蛋
3. 直接改遊戲
4. **測試門（沒得商量）**：一支測試把遊戲 JS 抽出來、把 DOM 打樁，無頭跑 **220 條完整人生**，斷言零 runtime error ＋一堆不變量（事件可達性、存檔完整性、壽命分佈）；另一支審 state machine 跟舊存檔相容。紅燈就不准上。
5. 部署到 Cloudflare Pages，寫好這輪 changelog 給下一輪看

跑了 79 輪，從一個 60 幾事件的雛形長成：696 事件、57 種死法、254 成就、23 種出身、還有種子重播系統（任何一條人生用短碼就能重播到一模一樣）——全部塞在**一個 ~1.5MB 的 HTML 檔**裡，沒框架、沒 build step、沒依賴，`file://` 點開就跑。每一輪都是一個 commit，整段進化史可考古。

**最有事的兩件事：**
- 它會自己維護 determinism。種子重播要能對齊，UI 程式碼就不能吃 RNG，它在自己的註解裡一再重申「UI 不准消耗亂數」，好讓重播逐位元一致。一個 AI 自己幫自己立規矩還真的遵守，比我有紀律。
- 它把測試門當鐵律，不是建議。220 條人生模擬只要抓到 regression，它就整輪拿去修、不上線。我當年趕進度時可沒這麼有骨氣。

遊戲本體是滿滿鬼島嘲諷：22K 開局地獄難度、責任制功德圓滿、珍珠嗆喉、天燈砸頂、排隊名店排到殉道……死法圖鑑 57 種，很多根本你我本人。

對自主迭代的迴圈設計、測試門、或 determinism 怎麼守有興趣的，歡迎在推文戰，code 全公開歡迎打臉。
